Armour your photos before AI can edit them.

Vajra adds a perturbation you cannot see, aimed at the image's representation inside a diffusion model. There are two versions, and the difference between them is measured, not claimed: the in-browser tool below closes 0.6% of the distance to a neutral latent, and the GPU tool in this repository closes 89% for the same invisible pixel budget. If you need protection that actually works, use the GPU tool.

The browser tool

Drop a photo, choose a budget, protect. Everything stays in this tab.

Read this first: the browser tool does not stop an AI edit

Measured against the real Stable Diffusion VAE, this engine moves the model's latent by 0.6% of the distance it would need to close, and changes what the model decodes your photo as by 2/255. That is not enough to break an edit. It runs in a browser because it uses a fixed linear stand-in for the VAE encoder — and a linear stand-in is not a weak version of the attack, it is a different thing. The tool that actually works

Same idea, real gradients: it backpropagates through the Stable Diffusion VAE and moves your photo's latent towards a flat grey target, which is the paper's equation (4). It needs a GPU, so it runs in Colab or on a desktop — not in the browser.

Or run it locally

Needs Python, torch and about 1 GB for the VAE:

pip install torch diffusers safetensors pillow
python3 research/sd_encoder_attack.py \
    photo.jpg --steps 200 --eps 0.12

On a CPU it is about 12 s per step at 192 px, so use --steps 20 --size 192 to try it and a GPU for real use.

How the protection works

Four steps, all of them arithmetic you could re-derive on paper.

  1. A fixed surrogate encoder

    Four random patterns are generated from your seed and band-pass filtered into the mid-frequency range — the band where the eye is least sensitive and where JPEG's quantisation table does the least damage. Each pattern wk is mean-removed and scaled to unit RMS. The image's embedding is the projection ek = mean(x · wk).

  2. A neutral target

    Every pattern has zero mean, so the embedding of a flat mid-grey image is the zero vector. That is the target: the protection pulls the image's mid-band structure towards flat, which is exactly the representation a diffusion model would read as "nothing to preserve here".

  3. Projected gradient descent

    The loss is ‖e(x)‖². Because the surrogate is linear its gradient is analytic — ∂loss/∂x = 2·Σ ekwk — so each step is a sign step with a decaying rate, followed by a hard projection back into the ε-ball around the original image. No model weights, no backprop through a network, no GPU.

  4. Budget split and masking

    The bound is enforced on RGB, not on luma, so the shift you can measure on any channel never exceeds ε. Luma takes half the budget and the rest is divided by the 1.402 and 1.772 chroma gains, so colour absorbs what the eye will not notice. Flat regions receive a fraction of the budget; textured regions receive all of it. The solve runs at 512 px and is bilinearly upsampled, which keeps it fast on a phone.

What this is — and what it is not

This is a deterrent, not a guarantee. Being clear about that is the whole point of the project.

  • The browser tool is not the paper's attack. The paper optimises against the real Stable Diffusion VAE with gradients from the actual network. The browser engine optimises against a fixed linear surrogate so it can run on a phone with no weights. Measured on the same image, at the same invisible pixel budget: the surrogate closes 0.6% of the latent gap and shifts the VAE's decoded view by 2/255; the real attack closes 89% and shifts it by 34/255. Only one of those breaks an edit.
  • It raises the cost, it does not prevent. A determined person can crop the image, photograph the screen, or denoise it. Each of those costs them quality, which is the entire objective.
  • Re-compression eats part of it. Use the survival probe before you post somewhere that re-encodes aggressively, and raise the strength if the number is low.
  • It is for your own photos. Protecting pictures of other people, or images you do not have the rights to, is not what this is for.
  • Keep the original. The protected file is meant to be published; the original is what you keep for yourself. Re-running the same seed reproduces the same protection.

This app does not protect against AI editing — it runs the same surrogate engine as the browser tool, which closes 0.6% of the latent gap. It is here because it is honest about that, not because it works. Use the GPU tool above.

Questions

Can I see the difference?

Barely. Switch to “Amplified difference” and raise the gain — that is the perturbation multiplied by up to 32×. At the default strength the image measures above 38 dB PSNR and above 0.97 SSIM against the original, which is the range where a viewer cannot tell them apart side by side.

Does it survive WhatsApp or Instagram re-compression?

Partly, and the survival probe tells you how much. Re-encoding at quality 80 typically keeps most of the mid-band energy because that is the band the perturbation lives in. Heavy re-compression at low quality removes more — raise the strength, or publish the PNG.

Does it stop AI editing completely?

No, and nothing on a consumer device does. It makes the edit look wrong, which is the documented goal of the original work: raise the cost of the attack rather than make it impossible. Treat any tool that claims otherwise with suspicion.

Is anything uploaded?

No. There is no server and no network call in the page or the app; the APK does not even request the internet permission. Open your browser's network tab while you use it if you want to check.

Can I undo it?

Keep the original file — that is the clean copy. A protected image can be degraded back towards the original by denoising or resampling, which is precisely the quality cost the protection imposes on anyone trying to edit it.

How does this relate to PhotoGuard?

Vajra is an independent reimplementation of the idea from “Raising the Cost of Malicious AI-Powered Image Editing” (Salman, Khaddaj, Leclerc, Ilyas and Madry, 2023).
